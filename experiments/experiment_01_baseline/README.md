# Experiment 01 — Baseline VLM

## Goal

Establish the first working vision-language baseline for DocGuard AI: a single
document image plus a single prompt, sent to a small open-weight VLM, with no
OCR, no fine-tuning, and no retrieval. This is a smoke test of the
infrastructure, not an accuracy benchmark.

## Setup

| Item | Value |
|------|-------|
| Model | `HuggingFaceTB/SmolVLM-256M-Instruct` (~256M params) |
| Dtype | `float32` |
| Device | `cpu` |
| Decoding | greedy (`temperature = 0.0`) |
| Test image | `data/synthetic/synthetic_invoice.png` (synthetic, generated by `scripts/create_synthetic_invoice.py`) |

Prompts come from `src/document_understanding/prompts.py`: `describe`,
`classify`, `key_value`, `qa`.

## Reproduce

```bash
python scripts/create_synthetic_invoice.py
python scripts/run_vlm.py --image data/synthetic/synthetic_invoice.png \
    --prompt "Describe this document." --pretty
python scripts/run_vlm.py --image data/synthetic/synthetic_invoice.png \
    --prompt-template qa --question "What is the invoice number?" --pretty
```

## Results

Recorded in `results.json`. Measured on a CPU-only Linux VM (Python 3.10,
torch 2.13.0+cpu, transformers 5.15.0) — not on the Windows development
machine, so timings there will differ.

- Inference time per prompt: ~10.7–14.3 s on CPU
- Peak process RSS: ~1.6 GB (whole process, not model-only)
- Classification and single-field QA were correct on the synthetic invoice
- Free-form key-value extraction did not follow the requested output format

## Limitations

- Single synthetic sample; no quantitative accuracy metric was computed
- Memory is reported as process RSS via `psutil`; no CUDA memory (no GPU)
- A 256M-parameter model is enough to validate the pipeline, not to trust
  structured extraction quality

## Next

Compare a larger checkpoint (e.g. `HuggingFaceTB/SmolVLM-500M-Instruct`) on GPU
against this baseline before drawing quality conclusions.
